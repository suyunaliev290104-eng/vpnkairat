# VPN-сервис в Telegram с мини-приложением — дизайн

## Зачем
Свой коммерческий VPN, который продаётся и управляется целиком внутри Telegram:
клиент открывает бота → мини-приложение → оплачивает → сразу получает ключ и
инструкцию. Главное — удобный, «продуктовый» интерфейс и полностью свой код.

## Цели
- Продажа подписок: пробный период, тарифы 1 / 3 / 6 / 12 мес.
- Автовыдача ключа VLESS+Reality (ссылка подписки + QR) сразу после оплаты.
- Оплата: Telegram Stars, CryptoBot (Crypto Pay API) и lava.top (карты РФ/СБП
  и зарубежные карты, без своего ИП — lava.top выступает платёжным агентом).
  ЮKassa — подключается позже одним модулем без правок остального кода.
- Мини-приложение: статус подписки, срок, трафик, выбор тарифа, оплата,
  ключ/QR, инструкции под iOS / Android / Windows / macOS, рефералы, поддержка.
- Бот: /start, кнопка открытия мини-приложения, уведомления (оплата прошла,
  подписка кончается через 3 дня / 1 день, закончилась).
- Реферальная программа: бонусные дни за оплату приглашённого.
- Админка (в боте): статистика (пользователи, активные, выручка), поиск
  пользователя, выдать/продлить дни, рассылка, управление серверами.
- Несколько VPN-серверов (локаций); пользователь получает доступ ко всем
  через одну ссылку подписки.

| 12 мес | 1190 ₽ | 99 ₽ | −38% | 1080⭐ | 14 USDT |

В мини-приложении у каждого тарифа показываются цена за месяц и бейдж
выгоды («−38%», «Выгоднее всего» на 12 мес, «Популярный» на 3 мес).

Пробный период 3 дня (один раз на аккаунт), трафик без лимита, до 3 устройств,
реферал: +7 дней пригласившему за каждую оплату приглашённого.

## Не цели (MVP)
- Свой клиент-приложение для VPN (используем Happ / v2RayTun / Hiddify / Streisand).
- Веб-сайт вне Telegram.
- Автоматическое продление (рекуррентные списания).
- Промокоды — вторая очередь.

## Анти-цели
- Утечка ключа одного пользователя к другому, выдача доступа без оплаты.
- Двойное начисление дней за один платёж (повторный webhook).
- Мини-приложение, доверяющее данным клиента без проверки подписи initData.

## Ограничения
- VPN-серверы — VPS за рубежом, арендует владелец; на каждом стоит 3x-ui.
- Протокол VLESS + Reality (устойчив к блокировкам в РФ).
- Stars: цены в XTR; CryptoBot: цены в USDT; lava.top: в RUB; ЮKassa позже — в RUB.
- lava.top: каждый тариф заводится в кабинете lava.top как отдельный «оффер»;
  его offerId кладётся в конфиг. Платёж создаётся через их API
  (`POST /api/v2/invoice`, заголовок `X-Api-Key`, поля email, offerId,
  currency), клиент уходит по paymentUrl, результат приходит вебхуком.
  lava.top требует e-mail покупателя (для чека) — мини-приложение спрашивает
  его один раз и запоминает. Вебхук проверяется по секретному ключу,
  заданному в настройках вебхука lava.top, а статус дополнительно
  перепроверяется запросом к их API. Точные поля API сверить с актуальной
  документацией gate.lava.top при реализации (в этой сессии сайт недоступен).

## Подходы (рассмотрены)
- **A. Свой бот + мини-приложение поверх 3x-ui** — ВЫБРАН. Свой код, любой UI,
  простая установка серверов.
- B. Поверх Remnawave — лучше для 5+ серверов, но тяжелее на старте.
  Учтено: доступ к панели идёт через интерфейс `VpnProvider`, чтобы потом
  можно было заменить 3x-ui на Remnawave.
- C. Готовый open-source бот — быстро, но чужой продукт и шаблонный UI.

## Архитектура (решения владельца отмечены ✅, остальное — мой выбор)
- ✅ Оплата Stars + CryptoBot + lava.top, ЮKassa — одним модулем.
- ✅ Панель 3x-ui, VLESS+Reality.
- Бэкенд: Python 3.12, FastAPI (API мини-приложения + вебхуки платёжек) и
  aiogram 3 (бот) в одном процессе; SQLAlchemy 2 async + PostgreSQL
  (SQLite для локальной разработки); APScheduler для напоминаний/отключений.
- Мини-приложение: React + Vite + TypeScript, Telegram WebApp SDK, тема
  берётся из Telegram (светлая/тёмная), отдаётся тем же FastAPI.
- Платежи: интерфейс `PaymentProvider` (`create_invoice`, `handle_webhook`)
  + реестр провайдеров. Новая платёжка = новый файл + строка в .env.
  Идемпотентность: уникальный `provider_payment_id`, начисление только при
  переходе `pending → paid`.
- VPN: интерфейс `VpnProvider` (`create_client`, `extend`, `disable`,
  `get_traffic`). Реализация `XuiProvider` через HTTP API 3x-ui. Клиент
  создаётся на всех активных серверах с одним UUID/subId.
- Ключ: ссылка подписки (`/sub/<token>` на нашем бэкенде, отдаёт base64-список
  vless-ссылок всех серверов) — так добавление сервера не требует перевыдачи.
- Авторизация мини-приложения: проверка HMAC `initData` по токену бота.
- Деплой: docker-compose (app + postgres + caddy с HTTPS). Отдельный скрипт
  установки 3x-ui с Reality на VPN-сервер.

## Данные
users (tg_id, username, email, referrer_id, created_at, is_admin),
subscriptions (user_id, expires_at, uuid, sub_token, traffic_limit, trial_used),
servers (name, country, flag, panel_url, login, password, inbound_id, enabled),
payments (user_id, provider, provider_payment_id UNIQUE, amount, currency,
plan_id, status, created_at), plans (конфиг в коде/.env).

## Оставлено исполнителю
Точный дизайн экранов (в стиле Telegram, карточки, крупная кнопка
«Подключиться»), тексты, цены по умолчанию (меняются в конфиге),
структура тестов.
